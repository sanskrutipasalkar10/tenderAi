| 25 | `classify.py`'s table-grid line-length threshold | 10pt (original) vs. recalibrated against real documents | 60pt (`MIN_LINE_LENGTH`) | Ran the classifier against 8 real Indian government tender PDFs (1197 pages, `documents/`). Real table borders on the same document measured 495-755pt. 60pt keeps margin above the measured noise ceiling while still clearing small legitimate tables (a 2-3 row synthetic fixture's vertical border is ~78pt) — both the golden eval (100%, 109/109) and the real-document false positive were re-verified after the change | Another real document produces line-art noise longer than 60pt — consider a page-relative percentage instead of an absolute point value (noted as residual risk in classify.py's own comment) |
| 26 | `extract_table_structure`'s header-row detection | Always treat row 0 as the header vs. detect the real header row | Skip leading "preamble" rows (single populated cell, e.g. a section title or enquiry number spanning the row) to find the first "dense" row; if that row's first cell is a bare serial number (`_looks_like_data_row`), treat it as a continuation page with no header of its own rather than mislabeling a data row as a header | Found on the same 8-real-document run: BHEL's 135 real BOQ-style tables have 1-3 title/metadata rows before the actual column-header row, confirmed by inspecting pdfplumber's raw row output directly. The naive "row 0 = header" assumption produced a title fragment as "headers" on 130/135 tables. Multi-page tables also repeat the SAME preamble on every continuation page without repeating the real header row — an earlier, looser fix (any row with >=half its columns populated is "the header") wrongly claimed a data row as the header on those pages; the serial-number check fixes that specifically. Re-verified: 69 pages now get a real detected header, 69 are correctly flagged as headerless continuations (all rows preserved as data, none dropped), 0 pages lose all their rows, 2715 total data rows captured — up from a state where 130/135 tables had a misleading header and this count wasn't even being measured correctly | A table's real column-header row doesn't start each section on a fresh page (i.e. this pagination pattern isn't universal) — this is inherently a per-page heuristic; genuine cross-page table-continuation tracking is a Phase 4 concern (chunking has multi-page context this doesn't) |
